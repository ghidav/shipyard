# Changelog

## 0.1.0 (unreleased)

The first release.

- **Blueprints.** A blueprint is a directory holding a `run.toml` with `[agent]` (the model, its harness and its modules), `[data]` and `[recipe]`, and optionally `[rollout]`, `[checkpoints]` and `[logging]`. A key left in the table it moved out of is refused with where it lives now. `shipyard check` prints the config as resolved and every problem at once, before anything is spent.
- **Six recipes.** `evaluate` measures. `dapo`, `dr-grpo` and `cispo` train, each a fixed preset of advantage, loss and clipping. `gepa` evolves the skills a harness reads. `fst` alternates gepa and training steps in cycles (fast-slow training). Any recipe can carry skills, directories holding a `SKILL.md`, into every rollout.
- **The trainer is the run.** A trainer opens the agent, takes `[recipe] steps` steps (`sample`, then `step`, which returns a `TrainingStep`), measures the test set and checkpoints `final`. A trainer takes a blueprint and a directory to write into, so it runs from Python without a run: `with DAPOTrainer(config, directory) as trainer: await trainer.train()`. A Python file defining one `Trainer` subclass, passed after the blueprint, replaces the kind's trainer; the run keeps a copy and resumes under it. `shipyard.training` exports `Trainer` and every recipe's class to subclass, and `shipyard` exports `Blueprint`, `load` and `Trainer`.
- **Runs.** Every run writes `runs/<blueprint>__<7 chars>/`: `run.toml` copied byte for byte, `process.json`, `metrics.jsonl`, `jobs.jsonl`, `requests.jsonl`, `checkpoints.jsonl`, `costs.json`, `modules/`, and `proxy.log` when it serves. `shipyard runs` lists them. `shipyard show` prints one.
- **Loggers.** The trainer writes its rows, jobs, checkpoints and costs through loggers: the run directory always, and a wandb run named after the run with `[logging.wandb]` (the `shipyard[wandb]` extra). A trainer subclass adds its own in `loggers()`, and the trainer closes them when it exits. A run is what `shipyard run` wraps around a trainer: it opens, reopens and closes its directory and notes who ran it and how it ended.
- **Datasets as directories.** A dataset is `tasks/<name>/`, one Harbor task per subdirectory. A blueprint may name a list. Batches are an endless stream, reshuffled with the seed at each pass, and a run is counted in `[recipe] steps`.
- **Secrets that are identities.** `[rollout.secrets]` names a variable each trial holds alone, from a pool in shipyard's environment: one value per trial in flight, held from before Harbor starts the trial until after its teardown, and scrubbed from the trial's directory. A trainer's `secrets` method returns its own `Secrets` for other logic, such as a key made for each trial.
- **Rollouts on Harbor.** One Harbor job per batch, under `jobs/<run id>-NNNN/`, on any Harbor sandbox. Profiles wire `pi`, `claude-code`, `opencode` and `terminus-2`. Any other Harbor agent runs with the generic OpenAI wiring.
- **The proxy.** `shipyard serve` serves Tinker weights in the OpenAI and Anthropic dialects, behind a harness token, and records every model call as token ids and logprobs. A separate control token re-points it at new weights.
- **Training targets by token prefix.** A call whose prompt extends the previous prompt and completion continues its sequence. Any other call starts a new one. Each completion is trained on exactly once.
- **Admission.** A rollout with no result, no reward, no model calls on record, a cut clock, a failed endpoint, an image, or a first prompt that did not fit is masked, with its reason on the job row. A masked rollout enters no mean, but a zero does.
- **The training step.** Each step publishes the weights, points the proxy at them, samples, credits, then runs `forward_backward` and `optim_step` over the Tinker SDK, on any backend that implements it (`TINKER_BASE_URL`). A checkpoint is saved every `[checkpoints] every` steps, and a final one is always saved. A continuation is a new run from `[agent] from_checkpoint`.
- **Costs as counts.** Tokens in, cached and out per party, training tokens, and sandbox seconds per sandbox, in `costs.json`.
